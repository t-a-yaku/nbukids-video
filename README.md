# Відеотека НБУ для дітей

Сайт, що збирає відео бібліотеки з YouTube і Медіатеки в одному місці.

## Як це працює

1. **Реєстр джерел** — Google-таблиця на спільному диску «Відеотека». Що показувати на порталі, вирішують працівники бібліотеки саме там: вкладки «Джерела», «Розділи», «Прив'язки», «Презентації».
2. **Щонічне оновлення** — завдання `.github/workflows/update-data.yml` щодня о 03:17 за Києвом запускає `scripts/collect.py`. Скрипт читає реєстр, збирає відео з усіх увімкнених джерел і зберігає `data/videos.json`.
3. **Сайт** — те саме завдання запускає `scripts/build_site.py`: з `data/videos.json` збираються окремі сторінки для кожного розділу, серії, регіону (усі 27) і кожного відео, карта сайту і robots.txt. Скрипт `tests/test_site.py` перевіряє посилання й розмітку, і лише тоді сайт публікується на GitHub Pages. Вигляд сторінок — у папці `site_src/` (шаблони і стилі).

## Адреса сайту і пошуковики

Налаштовується двома рядками на початку `.github/workflows/update-data.yml`:

- `SITE_URL` — постійна адреса сайту (зараз тимчасова, на github.io).
- `SITE_INDEX` — `"ні"` для демоверсії (пошуковики сайт не індексують, угорі смужка «Демонстраційна версія»); `"так"` — коли сайт переїде на адресу бібліотеки.

Посилання всередині сайту відносні, тому той самий набір сторінок працює і на піддомені, і в папці сайту бібліотеки.

**Піддомен video.chl.kiev.ua:** у DNS бібліотеки — запис `CNAME video → t-a-yaku.github.io`; у репозиторії Settings → Pages → Custom domain → `video.chl.kiev.ua`, позначити Enforce HTTPS; у workflow `SITE_URL: https://video.chl.kiev.ua/` і `SITE_INDEX: "так"`. Старі адреси github.io автоматично переадресуються.

**Папка chl.kiev.ua/videoteka/:** `SITE_URL: https://chl.kiev.ua/videoteka/`, `SITE_INDEX: "так"`; готовий сайт — архів `github-pages` у підсумку кожного запуску (вкладка Actions); його вміст копіюється в папку на сервері. Оновлення в цьому варіанті потребує копіювання щоразу або окремого налаштування на сервері.

## Доступи (без жодного спільного пароля)

| Що | Де | Хто керує |
|---|---|---|
| Реєстр джерел | Спільний диск «Відеотека» (Google Workspace chl.kiev.ua) | група video@chl.kiev.ua |
| Читання реєстру скриптом | Робот `videoteka-reader@videotekachl.iam.gserviceaccount.com`, доступ «Читач» до таблиці | власники проєкту Google Cloud `videotekachl` |
| Вхід GitHub → Google Cloud | Безключове підключення (Workload Identity Federation), довіряє лише цьому репозиторію | власники проєкту Google Cloud |
| Ключ YouTube Data API | Секрет репозиторію `YOUTUBE_API_KEY`; ключ обмежений лише YouTube Data API v3 | власники репозиторію |

Докладно — у документі «Хто володіє відеопорталом НБУ для дітей» на спільному диску.

## Запуск вручну

Вкладка **Actions** → «Оновлення даних відеотеки» → **Run workflow**. Звіт про кожне джерело видно в підсумку запуску.

## Якщо щось не працює

- Джерело з позначкою ⚠️ у звіті: для нього залишаються дані з минулого запуску. Найчастіше причина — неправильний ідентифікатор у реєстрі або плейлист став приватним.
- Помилка доступу до таблиці: перевірте, що роботу відкрито реєстр на перегляд.
- Репозиторій перенесено або перейменовано: виконайте в Cloud Shell блок «Якщо репозиторій перенесено» з кінця `setup/cloud-shell.sh`.
- Розклад GitHub вимикає, якщо в репозиторії 60 днів не було змін. Тоді його вмикають кнопкою на вкладці Actions.

## Перевірка скрипта

```
python tests/test_collect.py
pip install -r requirements.txt
python scripts/build_site.py      # сайт з'явиться в папці _site
python tests/test_site.py _site
```
