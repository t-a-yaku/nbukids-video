# Відеотека НБУ для дітей

Портал, що збирає відео бібліотеки з YouTube і Медіатеки в одному місці.

## Як це працює

1. **Реєстр джерел** — Google-таблиця на спільному диску «Відеотека». Що показувати на порталі, вирішують працівники бібліотеки саме там: вкладки «Джерела», «Розділи», «Прив'язки», «Презентації».
2. **Щонічне оновлення** — завдання `.github/workflows/update-data.yml` щодня о 03:17 за Києвом запускає `scripts/collect.py`. Скрипт читає реєстр, збирає відео з усіх увімкнених джерел і зберігає `data/videos.json`.
3. **Портал** — сторінки лише показують дані з `data/videos.json`.

## Доступи (без жодного спільного пароля)

| Що | Де | Хто керує |
|---|---|---|
| Реєстр джерел | Спільний диск «Відеотека» (Google Workspace chl.kiev.ua) | група video@chl.kiev.ua |
| Читання реєстру скриптом | Робот `videoteka-reader@videotekachl.iam.gserviceaccount.com`, доступ «Читач» до таблиці | власники проєкту Google Cloud `videotekachl` |
| Вхід GitHub → Google Cloud | Безключове підключення (Workload Identity Federation), довіряє лише цьому репозиторію | власники проєкту Google Cloud |
| Ключ YouTube Data API | Секрет репозиторію `YOUTUBE_API_KEY`; ключ обмежений лише YouTube Data API v3 | власники репозиторію |

Докладно — у документі «Хто володіє відеопорталом НБУ для дітей» на спільному диску.

## Запуск вручну

Вкладка **Actions** → «Оновлення даних відеотеки» → **Run workflow**. Звіт про кожне джерело видно в підсумку запуску.

## Якщо щось не працює

- Джерело з позначкою ⚠️ у звіті: для нього залишаються дані з минулого запуску. Найчастіше причина — неправильний ідентифікатор у реєстрі або плейлист став приватним.
- Помилка доступу до таблиці: перевірте, що роботу відкрито реєстр на перегляд.
- Репозиторій перенесено або перейменовано: виконайте в Cloud Shell блок «Якщо репозиторій перенесено» з кінця `setup/cloud-shell.sh`.
- Розклад GitHub вимикає, якщо в репозиторії 60 днів не було змін. Тоді його вмикають кнопкою на вкладці Actions.
